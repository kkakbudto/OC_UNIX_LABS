----------------------------------------------------------
Конкурентный контейнер (Лабораторная работа 2)

Набор файлов (Dockerfile, lab2.sh, run_lab2.sh) для создания
и запуска Docker-контейнеров, выполняющих конкурентное
управление файлами в общем разделяемом томе без race condition.

----------------------------------------------------------
Состав файлов

Dockerfile  — инструкция сборки легковесного образа на базе Alpine Linux.
lab2.sh     — POSIX-совместимый shell-скрипт конкурентной работы с файлами.
run_lab2.sh — вспомогательный скрипт для создания тома, сборки образа
              и массового запуска 1, 10 или 50 контейнеров.
README.txt  — данное руководство.

----------------------------------------------------------
Описание работы скрипта lab2.sh

1. При запуске контейнер один раз генерирует уникальный случайный
   идентификатор (из /proc/sys/kernel/random/uuid, с резервным
   вариантом через /dev/urandom) и сохраняет его на всё время работы.

2. В бесконечном цикле выполняются две операции с паузой в 1 секунду
   между ними:
   - создание файла с первым свободным именем из последовательности
     001, 002, 003 и т. д., с записью идентификатора контейнера
     и порядкового номера созданного файла (1, 2, 3, ...);
   - пауза 1 секунда;
   - удаление созданного файла;
   - пауза 1 секунда.

3. Поиск первого свободного имени и создание файла выполняются
   атомарно:
   - при наличии утилиты flock (проверяется через command -v flock)
     используется эксклюзивная блокировка flock -x на служебном файле
     .lock в каталоге общего тома; внутри критической секции не
     запускаются внешние процессы и не выполняются операции ожидания
     или вывода в лог;
   - если flock недоступен (например, в BSD/macOS или минимальном
     окружении), скрипт выводит предупреждение и автоматически
     переходит на переносимый POSIX-режим атомарного создания файла
     через set -C (noclobber, флаг O_CREAT | O_EXCL).

4. При остановке контейнера (сигналы INT, TERM, HUP, QUIT)
   обработчик trap удаляет текущий файл контейнера (если он создан)
   и корректно завершает процесс. Сам файл .lock отдельным контейнером
   не удаляется (чтобы не нарушить блокировку по inode для остальных
   работающих экземпляров), а безопасно очищается скриптом run_lab2.sh
   после остановки всех контейнеров.

----------------------------------------------------------
Быстрый запуск (через run_lab2.sh)

Сделайте скрипт исполняемым:
  chmod +x run_lab2.sh

Запуск 1 экземпляра:
  ./run_lab2.sh 1

Запуск 10 экземпляров:
  ./run_lab2.sh 10

Запуск 50 экземпляров:
  ./run_lab2.sh 50

Остановка и удаление всех запущенных контейнеров (с очисткой .lock):
  ./run_lab2.sh stop

Полная очистка (контейнеры и разделяемый том):
  ./run_lab2.sh clean

----------------------------------------------------------
Ручной запуск командами Docker

1. Создать разделяемый том:
   docker volume create lab2_shared_vol

2. Собрать образ контейнера:
   docker build -t lab2-concurrent .

3. Запустить один контейнер:
   docker run -d --name lab2_1 -v lab2_shared_vol:/data lab2-concurrent

4. Запустить 10 или 50 контейнеров:
   for i in $(seq 1 10); do
     docker run -d --name "lab2_$i" -v lab2_shared_vol:/data lab2-concurrent
   done

   for i in $(seq 1 50); do
     docker run -d --name "lab2_$i" -v lab2_shared_vol:/data lab2-concurrent
   done

5. Проверить содержимое общего тома и файлов:
   docker exec lab2_1 sh -c 'for f in /data/[0-9]*; do echo "$f: $(cat "$f")"; done'

6. Посмотреть логи контейнера:
   docker logs lab2_1

7. Остановить и удалить контейнеры:
   docker rm -f $(docker ps -aq --filter "name=lab2_")

8. При необходимости очистить служебный .lock в томе:
   docker run --rm --entrypoint /bin/rm -v lab2_shared_vol:/data lab2-concurrent -f /data/.lock

9. Удалить том:
   docker volume rm lab2_shared_vol
